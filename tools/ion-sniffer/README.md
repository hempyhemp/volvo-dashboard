# Сниффер обмена ИОН ↔ ЭБУ (K-Line)

Снимает реальный обмен программы **ИОН (InjOnl.exe)** с ЭБУ Январь 5.1.61 по
K-Line — чтобы увидеть **точные команды и адреса**, которые ИОН читает
(в частности, откуда берёт абсолютное давление, тайминги, пачки чтения).

## Зачем так, а не сниф по проводу

K-Line однопроводная, но на линии одновременно может висеть только один
активный тестер: адаптер ИОН **или** ESP32, но не оба. Поэтому пассивно
слушать проводом нельзя. Вместо этого перехватываем у самого процесса ИОН
вызовы WinAPI работы с COM-портом через **Frida** — ИОН при этом работает
как обычно на своём COM1, ничего переставлять не нужно.

Снимаем: TX/RX байты с таймингами, смену скорости (`SetCommState`),
Read/Write таймауты (`SetCommTimeouts`), overlapped-чтения.

## Установка (один раз)

```
python -m pip install frida frida-tools
```

(нужен обычный Python; проверено на 3.13.)

## Запуск

Из корня репозитория:

```
python tools/ion-sniffer/sniff_ion.py
```

или

```
powershell -ExecutionPolicy Bypass -File tools\ion-sniffer\sniff.ps1
```

Что произойдёт:

1. Скрипт **сам запустит ИОН** и прицепится с первого байта.
2. В открывшемся окне ИОН нажми **«Подключить»** как обычно (COM1, 38400 —
   уже стоят в InjOnl.ini).
3. В консоли пойдёт живой обмен; он же пишется в файл
   `tools/ion-sniffer/ion_sniff_<дата>.log`.
4. **Ctrl+C** — остановить. Пришли мне лог-файл.

### Если ИОН уже открыт / spawn не сработал

Запусти ИОН руками, подключись, затем:

```
python tools/ion-sniffer/sniff_ion.py --attach
```

### Другой путь к ИОН

```
python tools/ion-sniffer/sniff_ion.py --exe "D:\path\to\InjOnl.exe"
```

## Замер-эталон на машине (три режима)

Цель — перестать гадать по байтам: снять обмен и **одновременно** записать,
что в этот момент показывает сам ИОН. Тогда масштабы полей кадра считаются
однозначно.

Что закрываем этим замером:

| Вопрос | Чем закрывается |
|---|---|
| Масштаб `GBC` (у нас принято `кг/ч = GBC/10`, выведено из лога, не из прошивки) | «расход воздуха» / «цикловое наполнение» на экране ИОН |
| Линейно ли давление на верхах (проверено только на низах) | наддув на экране ИОН против `F80C` в кадре |
| `F80D` — это напряжение или младший байт АЦП ДАД (в коде и в доках сейчас расходятся) | напряжение бортсети на экране ИОН |
| Какое поле кадра — время впрыска (`F97B`/`F98D`/`F862`/`F841` не опознаны) | «время впрыска, мс» на экране ИОН |

### Подготовка

1. **Отключить ESP32 от K-Line.** На линии может быть только один тестер:
   либо адаптер ИОН, либо плата.
2. Запустить сниффер одной командой из корня репозитория:

```
powershell -ExecutionPolicy Bypass -File tools\ion-sniffer\sniff.ps1
```

3. В окне ИОН нажать «Подключить». В консоли сниффера пойдут строки
   `[0F]` с уже разобранными полями кадра.
4. Открыть в ИОН таблицу параметров так, чтобы одновременно были видны:
   **обороты, давление/наддув, расход воздуха (или цикловое наполнение),
   время впрыска, напряжение, температура воздуха**.

### Метки

Консоль сниффера принимает текст: напиши что-нибудь и нажми **Enter** —
строка уйдёт в лог с текущим временем. Так режим привязывается к байтам без
секундомера. Метки нужны в каждом режиме.

### Режим 1 — зажигание включено, мотор не заведён

Даёт атмосферное давление (опору для нуля наддува) и нули по расходу.

- Метка: `1 заглушен`
- Скриншот окна параметров ИОН.

### Режим 2 — прогретый холостой ход

Главный калибровочный режим: всё стоит на месте, можно спокойно списать
цифры.

- Метка: `2 хх прогретый`
- Скриншот окна параметров ИОН.
- Подержать 20–30 секунд.

### Режим 3 — под газом (наддув)

Здесь читать с экрана за рулём нельзя, поэтому:

- Метка: `3 газ` **перед** разгоном.
- Включить запись экрана: **Win+Alt+R** (Xbox Game Bar). Видео потом
  сопоставляется с логом по оборотам — они видны и там, и там.
- Разгон под нагрузкой до заметного наддува, потом сброс газа.
- Метка: `3 газ конец`.

Без записи экрана тоже сгодится: при выходе сниффер печатает **пики за
сессию** (максимумы `RPM`, `F80C`, `GBC` и кандидатов), их достаточно
сопоставить с максимальными значениями, которые показал ИОН.

### После

**Ctrl+C**, прислать `ion_sniff_<дата>.log` и скриншоты/видео.

## Формат лога

Сырой поток (только в файле, на экран не печатается):

```
    <сек> +<пауза,мс>  <напр>[<n>]  <hex-байты>  <разбор кадра>
```

Разобранный жирный кадр 0x0F (и в файле, и на экране раз в секунду):

```
    <сек>  [0F] RPM=… дрос=…% ОЖ=… возд=… V=… | F80C=… -> MAP~… кПа |
           GBC=… F82E=… F841=… F97B=… F98D=… F862=…
```

`MAP~` считается прямо из кадра по калибровке ДАД из прошивки
(`12.5 + 241·(F80C−10)/255`) — её и проверяем против экрана ИОН.
`F82E`/`F841`/`F97B`/`F98D`/`F862` пока не опознаны и печатаются сырыми.

Пример того, что ищем (адрес чтения давления):

```
   12.345 +48    TX[ 6]  82 10 F1 21 01 A5            -> SID 21 ReadDataByLocalId  LID=0x01
   12.360 +15    RX[47]  ...                           <- SID 61 ...
   12.408 +48    TX[ 8]  23 00 F9 A0 02 ...            -> SID 23 ReadMemoryByAddress  addr=0xF9A0 len=2
```

`->` = запрос (тестер→ЭБУ), `<-` = ответ (ЭБУ→тестер). Разбор — best-effort
по ISO 14230/KWP; если ИОН шлёт проприетарный OLT-кадр, сырой hex всё равно
виден полностью.

## Файлы

- `sniff_ion.js` — Frida-инструментация (хуки WinAPI).
- `sniff_ion.py` — драйвер: запуск/attach, приём событий, разбор, лог.
- `sniff.ps1` — обёртка для запуска одной командой.
