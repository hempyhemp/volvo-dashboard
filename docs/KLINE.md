# K-Line — ЭБУ Январь 5.1.61

Статус: **обмен работает** (2026-09-16). Дальше — расширять список
читаемых параметров (см. TODO внизу).

## Физика

- Донорская K-Line плата на LM339 (уже была распаяна и проверена ранее).
- ESP32 подключён через разъём **CN1** (GND-22-27-3V3) — единственный
  разъём платы CYD с двумя одновременно свободными GPIO. Подробнее про
  разъёмы платы — см. `docs/HARDWARE.md`.
  - **GPIO22** → TX (в K-Line/донорскую плату)
  - **GPIO27** → RX (из K-Line/донорской платы)
  - Общий GND с донорской платой и ЭБУ/OBD.
- Полярность — **прямая** (не инвертированная). Подтверждено self-echo
  тестом (см. `src/kline_test.cpp`): передали байт на TX, приняли на RX.
  При физической перестановке TX/RX местами эхо пропадает — то есть
  распайка "как есть" (без перестановки) верна, перепроверять не нужно.

## Протокол

**ISO 14230 (KWP2000), "быстрая инициализация".** НЕ 5-бодная медленная
инициализация ISO9141 и НЕ отдельная L-line — оба варианта пробовались
и не дали ответа от этого ЭБУ. Рабочий метод: порт открывается сразу на
**10400 бод**, никакого адресного байта на 5 бод не нужно.

Формат кадра: `[длина][адрес ЭБУ][адрес тестера][сервис/данные...][checksum]`,
checksum = сумма всех предыдущих байт кадра по модулю 256.

K-Line — однопроводная полудуплексная шина: в ответе сначала идёт **эхо**
байт, которые передал тестер, а затем настоящий ответ ЭБУ.

### Команды

| Команда | Байты | Успешный ответ содержит |
|---|---|---|
| `stopCommunication` | `81 10 F1 82 04` | (не проверяем, шлём "на всякий случай") |
| `startCommunication` | `81 10 F1 81 03` | `0xC1` |
| `readData` (RLI_ASS) | `82 10 F1 21 01 A5` | `0x61` |

Источник алгоритма и самих кадров — задокументированный рабочий код для
ЭБУ **Январь 7.2** (другая ревизия, тот же протокол/семейство), найден
через пользователя (DRIVE2). Проверено и подтверждено на реальном
Январь 5.1.61 21 сентября 2026: `0xC1` и `0x61` оба получены, 47 байт
суммарно в ответе на `readData` (6 байт эха + 41 байт настоящего ответа).

### Раскладка байт readData (подтверждено на реальном ЭБУ)

Индексы — от начала **полного** принятого буфера ответа на `readData`,
включая эхо нашего же запроса (6 байт) в начале:

| Индекс | Значение |
|---|---|
| `[10]` | `0x61` — позитивный ответ (SID + 0x40) |
| `[20]` | температура ОЖ + 40 → `°C = байт - 40` |
| `[22]` | положение дросселя, % |
| `[23]` | обороты двигателя / 40 → `RPM = байт * 40` |
| `[29]` | скорость автомобиля, км/ч |
| `[30]` | напряжение борт. сети → `U = 5.2 + байт * 0.05` |

Проверка: на столе с ЭБУ под напряжением, датчики не подключены —
получили температуру ≈20°C (комнатная) и напряжение ≈11.95В (похоже на
реальное питание от лабораторного БП) — оба значения адекватны реальным
условиям, это и есть подтверждение, что раскладка байт от Января 7.2
подходит и для 5.1.61.

Остальные байты ответа (топливо, соотношение воздух/топливо и т.д.) пока
не расшифрованы для этого конкретного ЭБУ.

## Автоподключение (без кнопки)

Раньше подключение запускалось только вручную по кнопке. Рассматривали
идею проверять готовность ЭБУ по уровню на RX ("idle=HIGH — значит ЭБУ
запитан"), но отказались: self-echo проходит даже без питания ЭБУ (это
проверка только своей же обвязки TX/RX, а не присутствия ЭБУ), а гадать
уровень K-line без осциллографа — рискованно.

Вместо этого — простой таймер с ретраями (как в найденном пользователем
референсном STM32-коде): пока не подключены — пробуем
`startCommunication`+`readData` раз в 2 секунды; после успеха переходим
на обычный опрос раз в 300 мс; если опрос перестал получать ответ —
снова переходим в режим переподключения. Кнопка на DEBUG осталась, но
теперь это просто ручной "переподключить сейчас" (плюс self-echo
sanity-check) — для нормальной работы она не обязательна.

## Код

- `src/kline_test.cpp` / `.h` — весь обмен по UART (ESP32-only, НЕ
  компилируется в PC-симуляторе).
  - `kline_test_poll(now_ms)` (вызывается из `loop()` в `main.cpp` на
    каждой итерации) — основной цикл: без подключения пробует
    подключиться раз в 2с, после подключения опрашивает `readData`
    каждые 300мс, при потере связи возвращается в режим переподключения.
  - Кнопка на вкладке DEBUG (`kline_manual_test`) — ручной вариант того
    же самого: self-echo → немедленная попытка подключения, в обход
    таймера.
  - Оба пути кладут результат в общий слой данных `kline_data.h`
    (`kline_data_set`); строку статуса на экране обновляют через
    `screen_debug_set_kline_result`.
- `lib/ui_demo/kline_data.h` / `.c` — простой C-геттер/сеттер без
  зависимостей от Arduino, общий для ESP32 и PC-симулятора.
  `kline_data_set()` вызывается только на ESP32; в симуляторе
  `connected` всегда `false`.
- `lib/ui_demo/screen_debug.c` — вкладка DEBUG сама читает
  `kline_data_get()` на своём `lv_timer` (раз в 200мс) и обновляет 2x2
  плитки живых данных (RPM/темп/дроссель/напряжение); `kline_test.cpp`
  никакие строки для этого не форматирует.
- `lib/ui_demo/screen_online.c` — параметры **RPM, COOLANT, VOLT**
  берутся из `kline_data_get()`, когда `connected == true`; остальные
  (BOOST, AIR_T, OIL_P, OIL_T, IGN) пока мок — байты для них ещё не
  найдены.
